# Панель категорій застосунків для Windows

Стартовий документ проєкту. Дата: 9 жовтня 2026 року.

## Мета

Створити Windows-застосунок, який допомагає організувати ярлики програм у категорії. Замість великої кількості закріплених значків користувач бачить компактну панель із вкладками категорій, а при наведенні на вкладку — вертикальну колонку застосунків.

Користувач не любить значки на робочому столі й зараз використовує закріплені програми на нижній панелі Windows. З часом їх стає забагато; нова тулза має спростити вибір потрібної програми.

## Узгоджений формат

- Це надбудова над стандартною нижньою панеллю Windows: власна панель розташовується безпосередньо над нею.
- Стандартна панель Windows продовжує виконувати свої функції: відкриті вікна, «Пуск», системний трей, годинник.
- Власна панель містить категорії, наприклад «Відео», «Розробка», «Ігри», «Тулзи».
- Наведення курсора на категорію відкриває над нею вертикальне меню з іконками застосунків.
- Натискання на застосунок запускає його.
- Користувач готує дизайн окремо. Він стане основою оформлення та уточнення взаємодій. Поточний документ не задає остаточні кольори, розміри чи композицію.

## Ключова вимога: видимість разом із панеллю Windows

Надбудова має бути видима в тих самих випадках, що й стандартна панель Windows. Не достатньо просто створити вікно, яке завжди знаходиться поверх інших.

Очікувана поведінка:

| Ситуація | Поведінка надбудови |
| --- | --- |
| Робочий стіл, панель Windows видима | Панель категорій видима над нею. |
| Звичайне або максимізоване вікно, панель Windows видима | Панель категорій доступна над панеллю Windows. |
| У Windows увімкнене автоматичне приховування, панель схована | Панель категорій також схована. |
| Користувач викликає приховану панель Windows біля нижнього краю | Панель категорій з’являється разом із нею. |
| Повноекранний застосунок приховує панель Windows | Панель категорій також прихована й не перекриває застосунок. |
| Панель Windows стає доступною поверх повноекранного застосунку | Панель категорій має слідувати її видимості. |
| Змінюється розмір або положення нижньої панелі Windows | Надбудова оновлює своє положення. |

Під час переходу курсора з категорії до її меню інтерфейс має залишатися доступним для вибору програми. Це потрібно узгодити з автоприховуванням: меню не повинно зникати посеред взаємодії.

Точний механізм синхронізації потрібно перевірити прототипом на цільовій Windows. Окрема AppBar сама по собі не доводить виконання цієї вимоги. Якщо поведінка системи створює обмеження, їх потрібно показати та обговорити до затвердження реалізації.

## Основний сценарій

1. Користувач бачить панель категорій над панеллю Windows або викликає їх біля нижнього краю екрана.
2. Наводить курсор на потрібну категорію.
3. Над категорією відкривається колонка застосунків.
4. Переводить курсор у меню та натискає потрібну іконку.
5. Програма запускається, меню закривається.

Відкриття та закриття меню повинні мати короткі налаштовувані або підібрані під час тестування затримки, щоб випадковий рух курсора не спричиняв мерехтіння. Escape закриває меню. Деталі підписів, анімацій і поведінки кліку по категорії уточнюються після отримання дизайну.

## Пропонований обсяг першої версії

Це робоча пропозиція для старту, яку можна уточнити після дизайну.

- Створення, перейменування, видалення та перестановка категорій.
- Додавання застосунків до категорії через вибір ярлика або перетягування.
- Відображення оригінальної іконки та назви застосунку.
- Перестановка й видалення ярликів із категорії; видалення ярлика не видаляє сам застосунок.
- Запуск застосунків із підтримкою параметрів і робочої папки, якщо вони задані в ярлику.
- Збереження категорій, порядку та налаштувань між запусками.
- Опційний автозапуск при вході в Windows.
- Доступні налаштування та явна команда виходу із застосунку.
- Коректне розташування з урахуванням масштабування екрана.
- Синхронізація видимості зі стандартною панеллю Windows.

## Поза початковим обсягом

- Повна заміна панелі Windows, «Пуск», системного трея або перемикача вікон.
- Автоматична зміна закріплених значків стандартної панелі Windows.
- Автоматичне перенесення чи видалення значків робочого столу.
- Хмарна синхронізація, облікові записи та магазин розширень.

## Попередній технічний напрям

Пропозиція: C# + WPF із Win32-взаємодією для позиціювання та інтеграції з оболонкою Windows. Це ще не затверджений вибір: спочатку необхідно перевірити ключову поведінку видимості та придатність для наданого дизайну.

Панель запуску та меню категорій — власні вікна застосунку. Конфігурація зберігається локально. Відсутній або недоступний ярлик має давати зрозуміле повідомлення без аварійного завершення програми.

Офіційна довідка щодо панелей біля краю екрана: [Using Application Desktop Toolbars — Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/shell/application-desktop-toolbars). AppBar підтримує резервування області екрана, сповіщення про зміни позиції та повноекранні застосунки. Синхронізацію з фактичною видимістю стандартної панелі потрібно дослідити окремо.

## Що уточнити в новому проєкті

- Дизайн від користувача: вигляд категорій, відкритого меню, налаштувань та редагування.
- Цільова версія Windows і конфігурація моніторів.
- Чи потрібна панель на кожному моніторі або лише на основному.
- Чи має панель резервувати місце для максимізованих вікон або перекривати невелику частину вікна над стандартною панеллю.
- Які типи запуску потрібні в першій версії: звичайні програми, Store-застосунки, Steam-ігри, папки та вебпосилання.
- Спосіб розповсюдження: portable-збірка чи інсталятор.

Ці питання не змінюють уже погоджений принцип: категорії над нижньою панеллю Windows і узгоджена з нею видимість.

## Критерії готовності першої версії

1. Користувач може створити категорію, додати реальний застосунок і запустити його з меню при наведенні.
2. Перехід курсора в меню не закриває його передчасно; вихід із меню та Escape працюють передбачувано.
3. Категорії та ярлики відновлюються після перезапуску.
4. Перевірені звичайні, максимізовані й повноекранні вікна, а також автоприховування панелі Windows.
5. Панель не залишається поверх повноекранної гри, коли стандартна панель Windows схована.
6. Зміна масштабування, роздільності та перезапуск Windows Explorer не залишають панель у неправильному положенні або в неробочому стані.
7. Інтерфейс відповідає дизайну користувача; перевірені порожні категорії та довгі списки застосунків.
8. Завершення роботи надбудови відновлює зарезервовану нею область екрана, якщо вона використовувалася.

## Порядок роботи після перенесення документа

1. Отримати дизайн і перевірити середовище нового проєкту.
2. Створити мінімальний технічний прототип: розташування над панеллю Windows, видимість, автоприховування, повноекранні вікна.
3. Перевірити прототип на комп’ютері користувача та зафіксувати обмеження.
4. Реалізувати панель і меню за дизайном, запуск програм та збереження конфігурації.
5. Додати редагування категорій, налаштування й автозапуск.
6. Перевірити погоджені сценарії та підготувати збірку для використання.
