# Перевірка прототипу

## Автоматичні перевірки

`scripts/build.ps1` виконує Release-build із warnings-as-errors і консольні перевірки. `-Publish` готує framework-dependent portable-вивід. Вимкнено shared compiler і workload resolver лише в build-скрипті, оскільки sandbox блокує службові named pipes/Service Control Manager; WPF не потребує workloads.

Runner перевіряє видимість desktop/maximized, відсутній Explorer, невидимість/cloaking, приховану смугу й offscreen auto-hide, показану панель, fullscreen із різним z-order, негативні координати монітора; JSON round-trip із українськими назвами й launch metadata, атомарний save, 5 копій, recovery після corruption, невідому schema, межі затримок і заборону порожніх назв.

Ці тести перевіряють модель, а не справжні переходи Shell. Статус реальних сценаріїв нижче не можна замінити зеленими unit-перевірками.

## Налаштування

`scripts/build.ps1 -VisualCheck` використовує реальні SettingsWindow-контроли й WPF-рендер. Перевірено чотири сторінки (Панель, Загальне, Категорії, Про програму), reload конфігурації після зміни слайдерів/сегментів/toggle, видиму помилку запису та успішний повторний save. Об’єкти використовують тестову конфігурацію в `.local`; реєстр автозапуску не змінюється. Усі PNG переглянуто візуально.

Увімкнення реального автозапуску при вході користувача ще не перевірено end-to-end. Команда реєстрації містить поточний `.exe` і абсолютний шлях конфігурації; зміна реєстру виконується тільки за кліком користувача.

## Реальна Windows 11

| Сценарій | Очікуваний результат | Статус |
| --- | --- | --- |
| Прочитати реальний Shell_TrayWnd через probe | Геометрія й видимість з Win32 | Підтверджено: 1920×1080, taskbar (0,1032)–(1920,1080), auto-hide off, ShouldShow=true |
| Старт і штатний вихід UI | Без аварії, трей прибрано | Smoke-запуск portable завершився з кодом 0 через 3 секунди; журнал підтвердив show=True |
| Desktop, звичайне й максимізоване вікно | Панель безпосередньо над taskbar | Потребує ручної перевірки |
| Увімкнений auto-hide, hidden/revealed | Обидві панелі ховаються/з’являються | Потребує ручної перевірки |
| Перехід із вкладки в меню при auto-hide | Можна вибрати програму, без передчасного закриття | Ризик: Shell може приховати taskbar; прототип тоді закриває меню |
| Справжня fullscreen-гра / відео | Панель не перекриває програму | Потребує ручної перевірки |
| Win викликає taskbar над fullscreen | Категорії слідують фактичному показу | Потребує ручної перевірки |
| Restart Explorer | Handle й позиція відновлюються | Потребує ручної перевірки; обробляється TaskbarCreated + poll |
| DPI 100/125/150/200%, resolution change | Правильні фізичні координати | Потребує ручної перевірки |
| Перезапуск app після змін | Категорії та порядок збережено | JSON-модель перевірено; UI-сценарій потребує ручної перевірки |

Під час перевірки залишайте `taskbar.log` поруч із конфігурацією. Не змінювати системні налаштування автоприховування без авторизації користувача. Реальне повторне відкриття Explorer й повноекранних програм теж виконувати як окремий тестовий сценарій.
